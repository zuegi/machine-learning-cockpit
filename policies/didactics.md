# Didactics Policy

- Start from a stated learning objective and prerequisites.
- Introduce notation and tensor shapes before operations.
- Progress from explicit mechanics to abstraction.
- Scratch code may be verbose or redundant when each step teaches something.
- Canonical library code remains concise, reusable, and maintainable.
- Keep examples small, deterministic, and runnable.
- Explain failures and limitations; do not hide them behind convenience APIs.
- Prefer mathematical correctness and teaching clarity over performance.
